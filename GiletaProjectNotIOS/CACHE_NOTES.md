# Кэширование новостей и изображений

## Что сделано

### 1. Отдельные слои
- `NewsRemoteDataSource` — только сеть.
- `NewsCacheService` — локальный кэш новостей в SQLite.
- `NewsRepository` — единая точка доступа для ViewModel, скрывает работу и с сетью, и с кэшем.
- `ImageCacheService` — кэш изображений: метаданные в SQLite, сами файлы в `cacheDir/news_image_cache`.
- `ImageRepository` — сначала память, затем файловый кэш, затем сеть.
- `AppContainer` — простая ручная DI-сборка зависимостей.

### 2. Политика кэша новостей
- **Fresh TTL = 5 минут**.
  - Если кэш моложе 5 минут, экран получает данные из SQLite без сетевого запроса.
  - Это ускоряет открытие экрана и убирает лишние загрузки.
- **Max TTL = 24 часа**.
  - Если сеть недоступна, можно показать последнюю сохранённую ленту.
  - Если кэшу больше 24 часов, он удаляется и больше не считается валидным.

### 3. Как кэш используется в UI
- При старте `NewsViewModel` сначала читает локальный кэш.
- Если данные есть, экран сразу показывает их.
- На экране есть явный баннер: `Показаны кэшированные данные...`.
- После этого запускается фоновое обновление.

Таким образом кэш не просто существует, а реально участвует в отображении.

### 4. Очистка кэша новостей
- При каждом чтении/обновлении вызывается `cleanupExpiredNews()`.
- Все записи старше 24 часов удаляются из таблицы `news_cache`.
- При успешном сетевом обновлении старый snapshot ленты заменяется новым.

### 5. Кэширование изображений (Android, без готовых решений)
- Готовые библиотеки для кэша изображений не используются.
- `coil` убран из экрана новостей.
- Изображения кэшируются так:
  1. сначала проверяется memory-cache (`LruCache`),
  2. потом SQLite + файл на диске,
  3. затем сеть.
- Файлы изображений хранятся в `cacheDir/news_image_cache`.
- В БД лежат: URL, имя файла, MIME, размер, время обновления и последнее использование.

### 6. Очистка кэша изображений
- `trimCache()` вызывается после сохранения нового файла.
- Удаляются:
  - файлы старше 7 дней,
  - самые давно неиспользованные файлы, если превышен лимит:
    - 50 МБ,
    - 120 файлов.
- Если в БД есть запись, но файла уже нет, запись удаляется при чтении.

## Почему такая схема хороша для задания
- UI не блокируется: сеть, SQLite и файловая система работают через `Dispatchers.IO`.
- Есть отдельные сервисы/репозитории.
- Кэш реально влияет на отображение.
- Есть прозрачная политика хранения и очистки.
- Есть бонусное кэширование изображений на Android через БД + файловую систему.
